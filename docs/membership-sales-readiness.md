# 会员售卖状态回归与真实支付前准备

## 目标

会员商品已经进入运营后台配置、公共快照和服务端 checkout 同源阶段。UX-AC 的目标不是接入真实支付渠道，而是先把运营改价、暂停、恢复售卖和历史待支付订单的关键边界工程化，保证后续接微信支付或支付宝时不会改变既有业务事实。

## 已固化的售卖状态规则

- 会员商品公共快照只返回 `active` 商品和 `active` 套餐，不返回后台审计事件。
- 商品 inactive 时，`GET /api/memberships/product` 返回 `CONFLICT`，错误 `details.reason` 为 `product_inactive`。
- 无 active 套餐时，`GET /api/memberships/product` 返回 `CONFLICT`，错误 `details.reason` 为 `no_active_plan`。
- 会员新订单创建以服务端 `CourseMembershipProductStore` 为唯一价格来源，订单金额写入 `subtotal`、`discountAmount` 和 `payableAmount` 后即成为历史订单事实。
- 后台改价只影响改价后创建的新订单，不改写已有待支付订单金额。
- 套餐暂停只阻止没有历史待支付订单的用户创建新会员订单；同一用户同一套餐已有待支付订单时，继续返回原订单并按原订单金额支付。
- 套餐恢复后，新订单重新可创建，并使用当前套餐价格。

## 回归用例矩阵

`server/modules/memberships/courseMembershipSalesRegression.test.ts` 覆盖以下链路：

| 场景 | 验证点 |
| --- | --- |
| 后台改价后读取公共快照 | 公共快照展示最新 `originalPrice/payablePrice`，且不包含 `auditEvents` |
| 后台改价后创建会员订单 | 新订单金额与 Store 当前套餐价格一致 |
| 历史待支付订单后改价 | 历史订单金额保持订单创建时的金额 |
| 暂停套餐后读取公共快照 | 返回 `CONFLICT` 和 `details.reason: no_active_plan` |
| 暂停套餐后新用户下单 | 新会员订单被阻断 |
| 暂停套餐后历史用户继续支付 | 返回同一待支付订单，金额保持不变 |
| 恢复套餐后新用户下单 | 新订单恢复创建，并使用当前价格 |

`server/modules/memberships/courseMembershipProductApi.test.ts` 额外覆盖商品 inactive 与套餐 inactive 的公共快照不可售原因。

## 真实支付接入前策略

### 待支付有效期

当前订单已有 `expiresAt` 字段，但会员待支付订单是否自动失效还没有统一服务端任务。接真实支付前建议建立统一过期策略：

- 默认保留 30 分钟到 2 小时，具体时长由运营策略决定。
- 过期后订单进入 `closed` 或 `expired` 类状态，不能继续支付。
- 过期关闭必须由服务端任务或读取时服务端状态机执行，不能由前端本地判断直接改写。
- 过期后用户重新下单时使用当前会员套餐价格和状态。

### 改价后的历史订单

历史待支付订单继续按订单记录金额支付，这是当前已固化策略。接真实支付时需要补两类保护：

- 支付请求金额必须使用订单 `payableAmount`，不能重新读取会员套餐当前价。
- 支付回调金额必须与订单 `payableAmount` 一致；不一致时进入异常，不交付会员权益。

### 暂停与恢复售卖

套餐暂停不是订单取消动作，只影响新订单创建：

- 暂停后，已有待支付订单仍可继续支付，除非订单已过期或被用户/后台关闭。
- 恢复后，新订单使用恢复时 Store 当前价格。
- 如果运营希望暂停时同步关闭历史待支付订单，需要另立后台动作并写入审计，不能作为隐式副作用。

### 支付成功与权益交付

当前开发期模拟支付由 `payCourseCheckoutOrderPayload` 直接确认。接真实支付后应保持以下边界：

- 创建订单只生成待支付订单，不交付会员权益。
- 支付渠道受理只记录渠道单号，不交付会员权益。
- 只有可信支付成功回调推进订单到 `paid`，并由服务端写入 `checkout_order` 会员来源。
- 重复回调必须幂等，会员来源订单 ID 不应被重复或错误覆盖。

### 退款边界

会员退款已经按来源订单回收权益。真实渠道接入后仍保持：

- 退款申请只进入 `refunding`，不直接写入 `refunded`。
- 退款成功只由渠道回调推进。
- 只有当前会员来源仍匹配退款订单，且没有其他有效会员订单覆盖时，才回收会员权益。

## 后续建议

- UX-AD：补会员待支付订单过期状态机和用户端过期提示。
- UX-AE：补真实支付渠道请求前的金额签名/渠道单号/回调金额一致性测试。
- UX-AF：补运营后台“关闭历史待支付会员订单”受控动作与审计。
