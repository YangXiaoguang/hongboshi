# 运营管理后台建设路线图

## 目标

红博士后续会逐步成为一个带有课程商品、咨询服务、用户权益、订单交易、支付退款、财务核算和风险复核的心理服务交易平台。运营管理后台不是简单的页面集合，而是承载业务状态机、权限、审计、对账和人工处理流程的稳定系统。

本路线图用于指导 Codex 持续二次开发：每个阶段都要能独立交付、可测试、可回滚，并且为后续阶段留下清晰的扩展点。

## 建设原则

- 共享契约优先：跨前后端的数据结构先进入 `shared/domain`，再由 client 和 server 消费。
- 服务端掌控状态：订单、支付、退款、咨询预约、财务和风险流转由 server service 决策，前端只提交意图。
- Store 抽象稳定：每个核心领域先定义 Store 接口，再提供内存/JSON/PostgreSQL 实现，API 不直接绑定数据库细节。
- 权限和审计内建：后台读写接口必须校验角色/权限；敏感操作必须记录操作者、对象、动作、前后状态和时间。
- 页面只做呈现：筛选、排序、状态推导、异常判断优先放在 feature repository 或 server service。
- 小步可交付：每个阶段都要有测试、文档更新、CI 验证、Git 提交和推送。

## M1: 统一后台框架

目标：把已存在的 `/admin/counseling` 和 `/admin/payments` 纳入统一后台体验，为后续课程、用户、订单、财务模块建立稳定骨架。

- 新增 `client/src/pages/admin/AdminLayout.tsx`，提供后台侧边导航、顶部上下文、权限提示和内容区域。
- 后台壳已从用户端 `AppHeader` 分离，授权、未登录和无权限状态均使用后台专用顶栏，后台页面不再展示用户端主导航。
- 新增 `client/src/pages/admin/AdminHome.tsx`，展示后台模块入口、关键风险提示和当前建设状态。

- 高风险事件不会只停留在日志里，当前已进入 `/admin/risk` 工作台。
- 复核动作有处理人、处理时间和结果，当前已写入 `RiskReviewStore`，并能记录 SOP 模板版本、升级摘要和审计中心投影字段。
- 敏感内容按权限展示，当前默认不输出测评答案、咨询前说明全文或风险信号原文。

## M9: 审计中心

目标：建立跨模块操作追踪能力。

交付内容：

- 统一审计事件契约。M9-A 已完成 `AuditCenterListResultSchema` 与 `AuditCenterEventSchema`，先以只读聚合方式复用既有审计事实，不新增写入真相源。
- 后台审计列表支持按操作者、对象、模块、动作、时间筛选。M9-A 已完成 `/api/audit/admin/events` 和 `/admin/audit`。
- 关键模块逐步接入统一审计。M9-A 已接入课程商品、会员、订单、交易、咨询运营和风险复核既有审计事实。
- 导出和事件详情基础能力。M9-B 已完成 `AuditCenterExportSchema`、`AuditCenterDetailResultSchema`、`/api/audit/admin/export` 和 `/api/audit/admin/events/:eventId`，复用同一套筛选、权限和隐私边界。
- 统一审计 Store 方案预研与只追加归档边界。M9-C 已完成 `AuditCenterArchiveEventSchema`、`docs/audit-store-architecture.md`、`audit_center_archived_events` 归档表草案和 schema 测试，明确保留现有业务 Store 真相源，只用归档表做长期检索和回填投影。
- 审计归档任务与只读校验试点。M9-D 已完成 `AuditArchiveStore`、PostgreSQL Archive Store、`POST /api/audit/admin/archive`、`audit:archive` 权限、归档映射、幂等写入、失败摘要和隐私裁剪测试，不做业务双写和读取切换。
- 归档后台入口与归档只读校验。M9-E 已完成 `/admin/audit` 管理员可见的归档触发/批次结果区、`GET /api/audit/admin/archive/verification`、归档/校验前端仓储和权限测试，默认仍不切换主列表数据源。
- 归档表只读检索预览。M9-F 已完成 `AuditCenterArchiveSearch*` 契约、Archive Store 长期检索筛选、`GET /api/audit/admin/archive/events`、前端归档预览仓储和 `/admin/audit` 管理员预览区，权限继续使用 `audit:archive`，默认仍不切换主列表数据源。
- 下一步 M9-G 建议做审计归档读取策略预研：设计按时间窗口读取切换、留存告警、迁移回滚和长期归档巡检方案，先形成可维护设计和小范围开关，不直接替换全量主列表。

验收标准：

- 敏感后台动作都能在审计中心追踪。
- 审计事件不可被普通后台操作修改。
- 审计查询性能有基础索引设计；当前归档表已包含模块、动作、资源、操作者、来源和归档时间索引，手动归档任务、只读校验和归档预览可验证幂等写入、回填覆盖、长期检索和归档差异。
